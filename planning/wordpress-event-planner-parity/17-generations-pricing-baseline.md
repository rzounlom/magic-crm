# 17 — Generations WordPress pricing as authoritative baseline

## Business decision

Generations confirmed the WordPress Event Planner pricing produces good results with real events. That effective configuration is the approved baseline for Generations inside MagicCRM. Do not redesign the model or substitute older MagicCRM prices.

## Effective WordPress pricing resolution (plugin 3.3.0)

| Component | How WordPress resolves it | Live value status |
| --- | --- | --- |
| Built-in catalog prices | `Catalog::defaults()` (`VERSION` `2026-11-02`) | Known (ported to `wpCatalogDefaults()`) |
| Admin overrides | `get_option('gapnext_price_overrides')` applied in `Catalog::all()` | **Not obtained** — requires live WP DB / admin export |
| Active custom packages | `get_option('gapnext_custom_packages')` → `Packages::active()` | **Not obtained** |
| Package inclusions / eligibility | Engine + `Packages::eligible()` (code rules + package fields) | Ported; live package rows missing |
| Weekday specials | Hardcoded engine rules | Ported |
| Food / catering | Catalog food keys + package food quantities | Defaults known; live overrides missing |
| Arcade credits | Engine allocation + package `credit` | Ported; live package credits missing |
| Private rooms | Catalog `rooms` / mezzanine / facility + inquiry flags | Defaults known; live overrides missing |
| Tax | Engine hardcodes **7%** F&B line tax (not a WP option) | Known |

**Missing for live integration:** the saved `gapnext_price_overrides` and `gapnext_custom_packages` from the Generations WordPress database (and any `gapnext_prices_updated` metadata). The plugin ZIP only ships defaults. No values were invented.

## Export procedure (standalone WordPress plugin ZIP)

Files: `tools/wp-parity/wordpress-plugin-export/`

1. Build: `cd tools/wp-parity/wordpress-plugin-export && ./build-zip.sh`
2. Upload `dist/magiccrm-gapnext-pricing-export-1.0.0.zip` via **Plugins → Add New → Upload Plugin** (does not edit Event Planner).
3. Activate; keep Event Planner 3.3.0 active.
4. **Event Planner → Export pricing** → download JSON (`effective_source: live_wordpress`).
5. Hand the file to MagicCRM import (below). Do not expose the download publicly.

See `tools/wp-parity/wordpress-plugin-export/INSTALL.md` for full steps and security notes.

The export includes catalog/rules version, effective prices, overrides option, active custom packages, tax note, timestamp, catalog revision, and configuration hashes. No customer/inquiry data.

## MagicCRM import (does not touch Production catalog rows)

```bash
# Optional: emit plugin-defaults snapshot for reconcile/pipeline tests only
pnpm exec tsx --tsconfig tsconfig.json scripts/wp-parity-export-plugin-defaults.ts

# After receiving a LIVE WordPress export:
pnpm exec tsx --tsconfig tsconfig.json scripts/wp-parity-import-pricing.ts \
  --org <organizationId> \
  --file /path/to/gapnext-effective-pricing-….json

# Compare against Generations booking-catalog seed (report only — no overwrite):
pnpm exec tsx --tsconfig tsconfig.json scripts/wp-parity-reconcile-pricing.ts \
  --file /path/to/export-or-plugin-defaults-snapshot.json
```

Import path:

- Parse `gapnext_effective_pricing_v1` (`pricing-export.ts`)
- Build `WpTenantParityConfig` with `pricingSource: tenant_live`
- Store under `scripts/data/wp-parity/tenant-packs/<organizationId>.json` (gitignored)
- Inquiry path loads via `loadWpTenantParityConfig` and labels staff UI `tenant_live`

Plugin-default snapshots **cannot** become `tenant_live` unless `--allow-plugin-defaults-snapshot` is passed for local tests.

## Reconciliation (plugin-defaults snapshot vs MagicCRM seed)

Until the live export arrives, reconcile uses the plugin-defaults snapshot against `scripts/data/generations-booking/booking-catalog.json`. Treat WordPress as the business baseline; do not silently merge.

Known example conflict already visible on defaults:

- `food.salad`: WP `2499`¢ vs MagicCRM `salad-pan` `1999`¢

Many WP keys (half-hours, pins, drink cards, some facility day bands, etc.) remain unmapped to MagicCRM SKUs. Birthday package SKUs in MagicCRM are a separate catalog model from WP custom packages.

Full markdown report: `17-pricing-reconciliation.md` (generated by the reconcile script).

## Calculation validation

- Existing plugin-default golden tests remain regression coverage (`wp-parity-engine-golden`, packages, arcade, PHP live compare).
- Import unit tests prove a `live_wordpress` export with overrides drives `tenant_live` totals and snapshots (`calculated_at`, revision).
- Exact cents parity against the **live** WordPress site still requires the live export + PHP engine run with that same effective catalog.

## Staff experience

When a verified pack is loaded:

- Pricing source: `tenant_live`
- Configuration revision on the private recommendation panel
- Calculation timestamp (`calculated_at`)
- Itemized prices / itinerary / warnings as today
- Plugin-default warning is **not** shown for those calculations

Without a live pack (current Production state): calculations remain `plugin_defaults` with the estimate warning. Staff review stays mandatory; no automatic customer quotes.
